## Client Builder

The client builder generates TypeScript definitions from Python controllers.
These definitions support editor suggestions and static type checking; they do
not change the values returned by requests at runtime.

## Evolution

In versions 0.1–0.8, the client builder read the server's OpenAPI schema.
That schema omitted some Python information the generated types needed:

- Controller inheritance was flattened into individual endpoints, losing the common
  ancestor types that TypeScript functions could otherwise accept.
- Enum values were preserved, but Python member names were lost. Generated names
  derived from the values could differ from the names in Python.

Version 0.9 began reading Python controllers directly, preserving inheritance
and enum names. Generation runs through three stages:

```
-> In-Memory Controllers

-> Parser: Extracts all metadata of the controllers/models necessary to generate TypeScript definitions

  -> ControllerWrapper
  -> FieldWrapper
  -> ActionWrapper
  -> ModelWrapper
  -> EnumWrapper

-> InterfaceBuilder: Takes the metadata and generates isolated TypeScript definitions for just that
  piece of the API

  -> ControllerInterface
  -> ModelInterface
  -> EnumInterface
  -> ActionInterface

-> FileGenerators: Write the full TypeScript files to disk, which often requires collecting
  multiple interfaces, tracking their imports, and assembling into a single file

```
