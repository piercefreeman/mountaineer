# Build Process

The client builder generates TypeScript definitions from Python controllers.
These definitions support editor suggestions and static type checking; they do
not change the values returned by requests at runtime.

This page describes the build internals for Mountaineer contributors.

## Evolution

In versions 0.1–0.8, the client builder read the server's OpenAPI schema.
That schema omitted some Python information the generated types needed:

- Controller inheritance was flattened into individual endpoints, losing the common
  ancestor types that TypeScript functions could otherwise accept.
- Enum values were preserved, but Python member names were lost. Generated names
  derived from the values could differ from the names in Python.

Version 0.9 began reading Python controllers directly, preserving inheritance
and enum names. Generation runs through three stages:

**In-Memory Controllers**: Load the Python controllers to inspect their signatures and runtime state.

**Parser**: Extract controller and model metadata into intermediate data classes.

  - ControllerWrapper
  - FieldWrapper
  - ActionWrapper
  - ModelWrapper
  - EnumWrapper

**InterfaceBuilder**: Turn that metadata into TypeScript interfaces and enums.

  - ControllerInterface
  - ModelInterface
  - EnumInterface
  - ActionInterface

**FileGenerators**: Combine definitions, resolve their imports, and write TypeScript files to disk.

## Native Development Runtime

`mountaineer-dev` owns the complete development lifecycle in Rust: file
monitoring, Vite, warm Python workers, backend health checks, and traffic
switching. A replacement backend must become ready before the proxy retires the
previous generation.

`mountaineer-watch` reuses the same Rust file monitor without starting a web
server. It loads the Python controller only when needed to regenerate the
managed TypeScript client files.

Python remains responsible for interpreting Python controller definitions.
Rust owns process supervision, debounce behavior, change classification, and
the command lifecycle.
